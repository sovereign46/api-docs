title: Errors & status codes
description: Stable JSON error envelope and code catalog.
---

JSON API errors use the envelope below. Branch on **HTTP status** plus **`error.code`**, not the human-readable `message`. Exceptions: [readiness](/docs/operations#readiness) returns a status body, and failures after streaming begins use protocol-specific [stream events](/docs/gateway#streaming).

## The envelope

```json
{
  "error": {
    "code": "invalid_request",
    "message": "invalid request"
  }
}
```

Some auth-bootstrap errors include extra fields (for example an `auth` object pointing at the login routes), but clients should always branch on status + `code`.

## Code catalog

Grouped by status class. Every `code` below is stable and safe to switch on.

### 4xx — request & auth

| HTTP | Code | When it fires |
| --- | --- | --- |
| `400` | `invalid_request` | Malformed path/query/body value, or an unsupported state. |
| `400` | `bad_json` | Request body is not valid JSON. |
| `400` | `unsupported_feature` | Responses/Anthropic input uses a feature outside the supported cloud subset. |
| `401` | `authenticate_first` | Browser/device approval needs an authenticated magic-link session first. |
| `401` | `unauthorized` | Missing, expired, revoked, or invalid bearer / cookie / worker credential. |
| `403` | `not_invited` | Email is not currently invited, or the invitation was revoked. |
| `403` | `forbidden` | Authenticated user lacks the owner/admin role, or the action is disallowed. |
| `403` | `model_not_allowed` | Requested model is not currently authorized and available for the caller's team. |
| `404` | `not_found` | Target does not exist or is not visible to the credential. |
| `405` | `method_not_allowed` | Route exists but the HTTP method is unsupported. |
| `409` | `conflict` | Resource conflict or duplicate state. |
| `409` | `idempotency_conflict` | `Idempotency-Key` reused with different parameters. |
| `410` | `expired` | Login, magic link, or token expired. |
| `412` | `precondition_failed` | A conditional requirement failed: for example, `If-Match` is stale, or an exact-release allow grant targets a release that is inactive or whose serving authority is unavailable. |
| `428` | `authorization_pending` | Polling target is not ready yet — see contexts below. |
| `428` | `precondition_required` | A required header such as `Idempotency-Key` is missing. |
| `429` | `rate_limited` | Request or stream rate limit exceeded. |
| `429` | `monthly_cap_exceeded` | The atomic monthly ledger cannot reserve the signed worst-case request cost; no upstream request was made. |

### 5xx — service & availability

| HTTP | Code | When it fires |
| --- | --- | --- |
| `503` | `email_unavailable` | Invite or magic-link email delivery is not configured or failed. |
| `503` | `model_registry_unavailable` | Independent registry verification has not succeeded or is no longer current. |
| `503` | `serving_authority_unavailable` | Exact deployment, activation, protected route, or challenged loaded identity is unavailable or invalid. |
| `503` | `model_unavailable` | No protected serving route or ready local model worker is available. |
| `502` | `upstream_error` | Model upstream request, status, or response failed. |
| `503` | `service_unavailable` | Control service is unavailable. |
| `503` | `rate_limiter_unavailable` | Rate-limiter backend is unavailable. |
| `500` | `internal_error` | Unhandled server-side failure. |

## `authorization_pending` contexts

This one code is shared by several polling-style endpoints — the caller should retry later. Branch on *endpoint context*, not on the assumption that it always means device login:

- Device login waiting for magic-link approval.
- Worker job leasing when no compatible work is available yet, or the worker cannot lease.

## Client guidance

| Situation | Do |
| --- | --- |
| `authorization_pending` | Retry after the endpoint-specific polling interval, or use exponential backoff. |
| `401 unauthorized` | Refresh credentials only if you hold a valid refresh token/cookie; otherwise restart login. |
| `403 forbidden` | Do not retry blindly; use credentials with the required role and scope, or choose an allowed action. |
| `403 model_not_allowed` | Select a model returned by authenticated gateway discovery, or ask an owner/admin to create an allow grant for that exact release. Retired model-ID policy cannot authorize it. |
| `412 precondition_failed` after a stale ETag | Re-read the resource, reapply the change, and retry with the current ETag. |
| `412 precondition_failed` while creating an exact-release allow grant | Do not treat it as an ETag retry. An operator must restore or provision serving authority for that exact active release before the grant can be created. |
| `503 model_registry_unavailable` | Wait for registry verification to recover; refreshing credentials or changing a grant does not repair trust. |
| `503 serving_authority_unavailable` | Wait for signed deployment/activation/loaded-route authority to recover; a broader grant cannot repair it. |
| `429 monthly_cap_exceeded` | Do not retry unchanged until capacity is available or an authorized administrator changes the cap. |
| `400 invalid_request` / `unsupported_feature` | Correct the payload, limits, or unsupported feature; do not retry unchanged. |
| retrying mutations | Preserve and reuse the same `Idempotency-Key` for safe retries. |
| `error.message` | Do not parse it — it is human-readable and may change. Use `code`. |
