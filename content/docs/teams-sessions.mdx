## Resolve team metadata

<Method method="GET" path="/v1/teams/{team}" returns="200 / 503" />
<EndpointMeta>Auth · **bearer / cookie**</EndpointMeta>

Path-escape the canonical team ID: `@s46/engineering` becomes `%40s46%2Fengineering`. Use this route for the team's gateway `endpoint`, `region`, `mode`, and configured `defaultModel`. In production, fetch the authoritative active model list separately from authenticated gateway `GET /v1/models` and verify that the default appears there.

```bash
curl 'https://api.s46.dev/v1/teams/%40s46%2Fengineering' \
  -H "Authorization: Bearer $S46_ACCESS_TOKEN"

curl https://gateway.s46.dev/v1/models \
  -H "Authorization: Bearer $S46_ACCESS_TOKEN"
```

Illustrative compatibility response:

```json
{
  "name": "@s46/engineering",
  "organizationSlug": "s46",
  "slug": "engineering",
  "endpoint": "https://gateway.s46.dev",
  "region": "EU-OPO",
  "mode": "cloud",
  "workerHosts": [],
  "defaultModel": "s46/example-published-model",
  "models": [],
  "modelMetadata": {}
}
```

The response above is fictional contract data, not a claim that any named model is live. Treat `models` and `modelMetadata` here as compatibility fields. They may be empty and do not establish an exact-release grant, current serving authority, or production availability.

Authenticated gateway model discovery is the authoritative production path. It returns only the caller team's exact-granted releases active under current [serving authority](/docs/serving-authority), with active runtime metadata under each OpenAI/Codex entry's `metadata`.

This team route can return `503 model_registry_unavailable` while resolving its cloud compatibility view. A successful team response is not evidence that serving authority is current; use gateway discovery and inference responses for the production authority result. Optional development overrides are `endpoint`, `region`, `mode`, and `defaultModel`; they do not select production serving transport. Airplane teams use local settings and may return `models` or `modelMetadata` as `null`.

## List sessions

<Method method="GET" path="/v1/sessions?team={team}" returns="200" />
<EndpointMeta>Auth · **bearer / cookie**</EndpointMeta>

```bash
curl 'https://api.s46.dev/v1/sessions?team=%40s46%2Fengineering' \
  -H "Authorization: Bearer $S46_ACCESS_TOKEN"
```

Returns `{ "sessions": [...] }`. Each session contains `id`, `state`, `harness`, `location`, `region`, `model`, `age`, `spent`, and `task`. Use `region`, not `lane`. This route lists sessions; it does not expose remote session-control actions.
