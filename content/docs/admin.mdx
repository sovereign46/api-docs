Admin routes require a bearer token whose user has `owner` or `admin` role for the target organization/team. `S46_ADMIN_TOKEN` is reserved for operator automation and must not be embedded in browser code.

Use this page in the order an admin consumer usually needs it: overview, organization setup, people/invitations, teams, integration policy, runtime control, then reporting.

## Route inventory

### Overview, usage, and audit

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/v1/admin/overview?organization={slug}&team={team}` | Counts and usage summary for the authorized scope. |
| `GET` | `/v1/admin/usage?team={team}&limit=100` | Usage events. |
| `GET` | `/v1/admin/audit?team={team}&limit=100` | Audit events. |
| `POST` | `/v1/admin/seed` | Operator/local default seed action. |

## Organizations

Organization create/update body:

```json
{
  "slug": "s46",
  "name": "Sovereign46",
  "displayName": "Sovereign46",
  "status": "active",
  "plan": "sovereign-team",
  "primaryRegion": "EU-OPO",
  "regions": ["EU-OPO"]
}
```

Organization member body:

```json
{
  "organizationSlug": "s46",
  "email": "new-admin@example.com",
  "role": "admin",
  "displayName": "New Admin",
  "status": "active"
}
```

## People and invitations

Invite one or more team memberships:

```json
{
  "email": "new-member@example.com",
  "organizationSlug": "s46",
  "teams": ["@s46/engineering"],
  "role": "member"
}
```

The older single-team body is also accepted:

```json
{
  "email": "new-member@example.com",
  "team": "@s46/engineering",
  "role": "member"
}
```

Invite responses include the user record and whether an email was sent:

```json
{
  "user": {
    "email": "new-member@example.com",
    "organizationSlug": "s46",
    "team": "@s46/engineering",
    "role": "member",
    "status": "active"
  },
  "emailSent": true
}
```

Revoke invite body:

```json
{
  "email": "new-member@example.com",
  "organizationSlug": "s46"
}
```

Person status update body:

```json
{ "status": "suspended" }
```

Team membership body:

```json
{
  "team": "@s46/engineering",
  "organizationSlug": "s46",
  "slug": "engineering",
  "role": "member",
  "displayName": "Engineering"
}
```

## Teams

Team create/update body:

```json
{
  "name": "@s46/engineering",
  "organizationSlug": "s46",
  "slug": "engineering",
  "displayName": "Engineering",
  "endpoint": "https://gateway.s46.dev",
  "region": "EU-OPO",
  "mode": "cloud",
  "workerHosts": [],
  "defaultModel": "s46/devstral-small-2-24b",
  "models": ["s46/devstral-small-2-24b"],
  "monthlyCapMicros": 100000000
}
```

Team responses may also include `memberCount`, `deviceCount`, `workerCount`, `spendMicros`, `createdAt`, and `updatedAt`.

## Jobs and schedules

Job create body:

```json
{
  "team": "@s46/engineering",
  "sessionId": "@dscape/auth-redirect-fix",
  "kind": "execution",
  "priority": 0,
  "region": "EU-OPO",
  "harness": "pi",
  "model": "s46/devstral-small-2-24b",
  "repository": "sovereign46/app",
  "branch": "main",
  "maxRuntimeSeconds": 3600,
  "maxCostMicros": 1000000,
  "payload": {}
}
```

`POST /v1/admin/jobs` and `POST /v1/admin/schedules` return `202 Accepted` with a job object.

Retry body:

```json
{ "runAfter": "2030-01-01T12:00:00Z" }
```

Schedule create body is the same as job creation but must include `runAfter`:

```json
{
  "team": "@s46/engineering",
  "sessionId": "@dscape/overnight-refactor",
  "kind": "execution",
  "runAfter": "2030-01-01T23:00:00Z",
  "runBefore": "2030-01-02T07:00:00Z",
  "maxRuntimeSeconds": 28800,
  "maxCostMicros": 25000000
}
```

Admin log routes are read-only. Workers do not append logs through the admin API.
