Admin routes require a bearer token whose user has `owner` or `admin` role in the target organization/team. `S46_ADMIN_TOKEN` is reserved for operator automation and must not be embedded in browser code.

All path parameters must be URL path-escaped. This is required for `{team}` (`@s46/engineering` -> `%40s46%2Fengineering`), `{email}` (`new-admin@example.com` -> `new-admin%40example.com`), worker IDs, job IDs, and device IDs.

## Auth used by the admin UI

The admin UI signs in through the same device flow as the CLI:

- `POST /v1/auth/device/start`
- `POST /v1/auth/device/poll`
- `POST /v1/auth/token/refresh`
- `POST /v1/auth/logout`
- `GET /v1/me`

See [Auth and account](/docs/auth).

## Organizations

- `GET /v1/admin/organizations`
- `POST /v1/admin/organizations`
- `GET /v1/admin/organizations/{slug}`
- `PUT /v1/admin/organizations/{slug}`
- `PATCH /v1/admin/organizations/{slug}`
- `GET /v1/admin/organization-members?organization={slug}`
- `POST /v1/admin/organization-members`
- `PUT /v1/admin/organization-members`
- `DELETE /v1/admin/organization-members?organization={slug}&email={email}`
- `GET /v1/admin/organization-roles`

Organization member roles are `owner`, `admin`, `member`, `viewer`.

Organization create/update body:

```json
{
  "slug": "s46",
  "name": "Sovereign46",
  "displayName": "Sovereign46",
  "status": "active",
  "plan": "sovereign-team",
  "primaryRegion": "EU-OPO",
  "regions": ["EU-OPO"]
}
```

Organization member body:

```json
{
  "organizationSlug": "s46",
  "email": "new-admin@example.com",
  "role": "admin",
  "displayName": "New Admin",
  "status": "active"
}
```

## Models

`/v1/admin/models` is the current operator-managed catalog surface:

- `GET /v1/admin/models`
- `POST /v1/admin/models` — operator token only
- `PUT /v1/admin/models` — operator token only

Org admins must not use catalog writes to publish weights. Certified publishing is a separate lifecycle where org admins upload artifacts and Sovereign46 re-runs verification server-side before assigning `backendModel`. In production this lifecycle requires scoped org owner/admin bearer credentials; `S46_ADMIN_TOKEN` is not a global model publisher.

Lifecycle endpoints:

- `POST /v1/admin/model-releases`
- `GET /v1/admin/model-releases?namespace={namespace}`
- `GET /v1/admin/model-releases/{releaseId}`
- `POST /v1/admin/model-releases/{releaseId}/upload-session`
- `POST /v1/admin/model-releases/{releaseId}/finalize-upload`
- `POST /v1/admin/model-releases/{releaseId}/validate`
- `POST /v1/admin/model-releases/{releaseId}/publish`
- `POST /v1/admin/model-releases/{releaseId}/yank`

`finalize-upload`, `validate`, `publish`, and `yank` require `Idempotency-Key`; release mutations require `If-Match`. See [Certified model publishing](/docs/models).

Catalog entry body for the existing operator path:

```json
{
  "id": "s46/devstral-small-2-24b",
  "displayName": "Devstral Small 2 24B",
  "provider": "s46",
  "region": "EU-OPO",
  "capabilities": ["chat", "code", "tools"],
  "contextWindow": 128000,
  "maxOutputTokens": 8192,
  "inputCostMicrosPerToken": 0,
  "outputCostMicrosPerToken": 0,
  "backendModel": "s46://models/s46/devstral-small-2-24b/releases/r000001/artifacts/sha256:...",
  "digest": "sha256:...",
  "status": "ready"
}
```

## Workers and jobs

- `GET /v1/admin/workers?team={team}&kind={kind}&region={region}&state={state}`
- `GET /v1/admin/workers/{id}`
- `GET /v1/admin/workers/{id}/logs?limit=100`
- `POST /v1/admin/workers/{id}/drain`
- `POST /v1/admin/workers/{id}/revoke`
- `GET /v1/admin/jobs?team={team}&state={state}&sessionId={sessionId}&kind={kind}`
- `POST /v1/admin/jobs`
- `GET /v1/admin/jobs/{id}/logs?limit=100`
- `POST /v1/admin/jobs/{id}/cancel`
- `POST /v1/admin/jobs/{id}/retry`

Job create body:

```json
{
  "team": "@s46/engineering",
  "sessionId": "@dscape/auth-redirect-fix",
  "kind": "execution",
  "priority": 0,
  "region": "EU-OPO",
  "harness": "pi",
  "model": "s46/devstral-small-2-24b",
  "repository": "sovereign46/app",
  "branch": "main",
  "maxRuntimeSeconds": 3600,
  "maxCostMicros": 1000000,
  "payload": {}
}
```

`POST /v1/admin/jobs` and `POST /v1/admin/schedules` return `202 Accepted` with a job object.

Retry body:

```json
{ "runAfter": "2030-01-01T12:00:00Z" }
```

Admin log routes are read-only. Workers do not append logs through the admin API.

## Schedules, usage, audit

- `GET /v1/admin/schedules?team={team}`
- `POST /v1/admin/schedules`
- `GET /v1/admin/usage?team={team}&limit=1000`
- `GET /v1/admin/audit?team={team}&limit=100`
- `GET /v1/admin/overview?organization={slug}&team={team}`
- `POST /v1/admin/leases/reconcile`

Schedule create body is the same as job creation but must include `runAfter`:

```json
{
  "team": "@s46/engineering",
  "sessionId": "@dscape/overnight-refactor",
  "kind": "execution",
  "runAfter": "2030-01-01T23:00:00Z",
  "runBefore": "2030-01-02T07:00:00Z",
  "maxRuntimeSeconds": 28800,
  "maxCostMicros": 25000000
}
```

These routes are live API routes even if parts of the product UI remain coming soon.
