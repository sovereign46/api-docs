---
title: Worker control
description: Worker registration, heartbeats, leases, lease acknowledgement, completion, and admin controls.
---

Workers are scoped to an organization and, when applicable, a team. The canonical scheduling dimension is `region`.

Worker control routes are JSON-only. Registration is admin-authorized; successful registration returns a worker token. Heartbeat, lease, completion, and internal lease acknowledgement use that worker token:

```txt
Authorization: Bearer <worker-token>
```

## Route inventory

| Method | Route | Auth | Purpose |
| --- | --- | --- | --- |
| `POST` | `/v1/worker/register` | owner/admin bearer | Register a worker and receive a worker token. |
| `POST` | `/v1/worker/heartbeat` | worker bearer | Update worker state, capacity, and model readiness. |
| `POST` | `/v1/worker/jobs/lease` | worker bearer | Lease compatible queued work. |
| `POST` | `/v1/internal/leases/ack` | worker bearer | Acknowledge a lease internally. |
| `POST` | `/v1/worker/jobs/complete` | worker bearer | Complete a leased job. |
| `GET` | `/v1/admin/workers?team={team}&kind={kind}&region={region}&state={state}` | owner/admin bearer | List workers. |
| `GET` | `/v1/admin/workers/{id}` | owner/admin bearer | Get worker plus recent logs. |
| `GET` | `/v1/admin/workers/{id}/logs?limit=100` | owner/admin bearer | Read worker logs. |
| `POST` | `/v1/admin/workers/{id}/drain` | owner/admin bearer | Request drain. |
| `POST` | `/v1/admin/workers/{id}/revoke` | owner/admin bearer | Revoke worker credential. |
| `GET` | `/v1/admin/jobs?team={team}&state={state}&sessionId={sessionId}&kind={kind}` | owner/admin bearer | List jobs. |
| `POST` | `/v1/admin/jobs` | owner/admin bearer | Enqueue a job. |
| `GET` | `/v1/admin/jobs/{id}/logs?limit=100` | owner/admin bearer | Read job logs. |
| `POST` | `/v1/admin/jobs/{id}/cancel` | owner/admin bearer | Cancel a job. |
| `POST` | `/v1/admin/jobs/{id}/retry` | owner/admin bearer | Retry a job. |
| `GET` | `/v1/admin/schedules?team={team}` | owner/admin bearer | List scheduled queued jobs. |
| `POST` | `/v1/admin/schedules` | owner/admin bearer | Schedule a job. |
| `POST` | `/v1/admin/leases/reconcile` | owner/admin bearer | Expire/requeue stale leases. |

## Register

`POST /v1/worker/register`

Requires `Authorization: Bearer <owner-or-admin-access-token>` scoped to the target team.

```json
{
  "team": "@s46/engineering",
  "kind": "execution_worker",
  "region": "EU-OPO",
  "version": "0.3.0",
  "endpoint": "https://worker-01.example",
  "protocol": "sse",
  "capabilities": ["vm_boundary", "pi"],
  "capacity": { "slots": 2, "maxConcurrent": 1 },
  "models": ["s46/devstral-small-2-24b"]
}
```

`kind` is one of:

- `execution_worker`
- `model_worker`
- `hybrid_worker`

Response `201 Created`:

```json
{
  "worker": {
    "id": "worker_01",
    "team": "@s46/engineering",
    "kind": "execution_worker",
    "region": "EU-OPO",
    "version": "0.3.0",
    "state": "ready",
    "capabilities": ["vm_boundary", "pi"],
    "capacity": { "slots": 2, "maxConcurrent": 1 },
    "models": ["s46/devstral-small-2-24b"],
    "createdAt": "2030-01-01T12:00:00Z",
    "updatedAt": "2030-01-01T12:00:00Z"
  },
  "token": "wkr_..."
}
```

Store the returned `token` securely; it is required for heartbeat, lease, acknowledgement, and completion calls.

## Heartbeat

`POST /v1/worker/heartbeat`

```json
{
  "workerId": "worker_01",
  "heartbeat": {
    "state": "ready",
    "capacity": { "slots": 2, "maxConcurrent": 1, "inUse": 0 },
    "models": ["s46/devstral-small-2-24b"],
    "modelDetails": [
      { "id": "s46/devstral-small-2-24b", "ready": true, "state": "ready" }
    ]
  }
}
```

Response `200 OK` is the updated worker record.

Worker states used by worker records include `starting`, `ready`, `busy`, `draining`, `unhealthy`, and `offline`. Model readiness states commonly include `missing`, `downloading`, `verifying`, `loading`, `ready`, and `failed`.

## Lease jobs

`POST /v1/worker/jobs/lease`

```json
{
  "workerId": "worker_01",
  "leaseSeconds": 300
}
```

Response `200 OK` when work is available:

```json
{
  "job": {
    "id": "job_01",
    "team": "@s46/engineering",
    "sessionId": "@dscape/auth-redirect-fix",
    "kind": "execution",
    "state": "leased",
    "priority": 0,
    "region": "EU-OPO",
    "harness": "pi",
    "model": "s46/devstral-small-2-24b",
    "workerId": "worker_01",
    "leaseId": "lease_01",
    "payload": {}
  },
  "lease": {
    "id": "lease_01",
    "jobId": "job_01",
    "workerId": "worker_01",
    "state": "active",
    "expiresAt": "2030-01-01T12:05:00Z"
  }
}
```

If no compatible work is available, the API returns `428 authorization_pending`. Treat that as “no lease yet” for this endpoint and poll again after backoff.

## Acknowledge leases

`POST /v1/internal/leases/ack`

```json
{
  "workerId": "worker_01",
  "jobId": "job_01",
  "leaseId": "lease_01"
}
```

Response `202 Accepted`:

```json
{ "acknowledged": true }
```

## Complete jobs

`POST /v1/worker/jobs/complete`

```json
{
  "workerId": "worker_01",
  "jobId": "job_01",
  "leaseId": "lease_01",
  "completion": {
    "state": "succeeded",
    "payload": { "summary": "completed" },
    "usage": {
      "eventType": "job_completed",
      "inputTokens": 1000,
      "outputTokens": 200,
      "costMicros": 4200000
    }
  }
}
```

Allowed completion states:

- `succeeded`
- `failed`
- `canceled`

Response `200 OK` is the updated job record.

## Admin controls and logs

Admin tooling can inspect and control workers/jobs through the admin routes listed above. Log routes are read-only:

```txt
GET /v1/admin/workers/{id}/logs?limit=100
GET /v1/admin/jobs/{id}/logs?limit=100
```

There is no public worker log-append endpoint. Job logs are written internally by lease acknowledgement/completion paths and by control-plane automation.

## Common failures

| HTTP | Code | Meaning |
| --- | --- | --- |
| 400 | `invalid_request` | Malformed JSON or unsupported state. |
| 401 | `unauthorized` | Missing/invalid worker token. |
| 403 | `forbidden` | Registration token is not owner/admin for the target team. |
| 404 | `not_found` | Worker, job, or lease does not exist or is not visible to the credential. |
| 428 | `authorization_pending` | No compatible lease is available yet, worker cannot lease yet, or capacity is full. |
