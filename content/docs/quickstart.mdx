Your email must have an active invitation for the target organization/team; otherwise login returns `403 not_invited`.

## CLI login

```bash
brew install sovereign46/tap/s46
s46 login --email you@s46.dev
```

The CLI handles device login and stores device-bound credentials. Use `s46 --help` for the commands in your installed release. For a custom client, follow the HTTP flow below.

## Start and approve login

```bash
curl -X POST https://api.s46.dev/v1/auth/device/start \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@s46.dev","deviceId":"dev-laptop","deviceName":"Dev laptop"}'
```

The response includes `deviceCode`, `userCode`, `verificationUri`, `intervalSeconds`, and `expiresAt`. Open `verificationUri` and complete browser approval. A GET validates but does not consume a magic-link token; approval requires POST.

## Poll for credentials

Poll no faster than the returned `intervalSeconds`:

```bash
curl -X POST https://api.s46.dev/v1/auth/device/poll \
  -H 'Content-Type: application/json' \
  -d '{"deviceCode":"s46_device_..."}'
```

`428 authorization_pending` means wait; `200` returns `accessToken`, `refreshToken`, and `expiresAt` plus account/team/device identity. Persist both tokens securely and save the newest rotating refresh token. See [Auth](/docs/auth) for complete login and refresh contracts.

## Call the gateway

Use the access token to resolve identity and team gateway settings, then call authenticated gateway discovery for the authoritative production model list. This example checks HTTP failures before using JSON and refuses an unavailable configured default rather than silently choosing another model:

```js
const accessToken = process.env.S46_ACCESS_TOKEN;
if (!accessToken) throw new Error("Set S46_ACCESS_TOKEN to your access token");

async function request(url, body) {
  const response = await fetch(url, {
    method: body ? "POST" : "GET",
    headers: {
      Authorization: `Bearer ${accessToken}`,
      ...(body ? { "Content-Type": "application/json" } : {}),
    },
    ...(body ? { body: JSON.stringify(body) } : {}),
  });
  if (!response.ok) throw new Error(`${response.status}: ${await response.text()}`);
  return response.json();
}

const me = await request("https://api.s46.dev/v1/me");
const team = await request(
  `https://api.s46.dev/v1/teams/${encodeURIComponent(me.team)}`,
);
const gateway = team.endpoint.replace(/\/$/, "");
const discovery = await request(`${gateway}/v1/models`);
const modelIds = discovery.data.map((model) => model.id);
if (!modelIds.includes(team.defaultModel)) {
  throw new Error("Choose an authorized model or ask an admin to update the default");
}
const completion = await request(
  `${gateway}/v1/chat/completions`,
  {
    model: team.defaultModel,
    messages: [{ role: "user", content: "Write a short status update." }],
  },
);
console.log(completion.choices[0].message.content);
```

Do not authorize from the team response's `models` or `modelMetadata`: those are compatibility fields, not exact serving-authority discovery. OpenAI/Codex gateway discovery returns active runtime hints under each model's `metadata`. Raw HTTP may omit `model` to request the configured team default; in production it still must resolve to an active, exact-granted release under current [serving authority](/docs/serving-authority). The gateway reserves worst-case monthly cost before dispatch and settles usage before completing the response or stream terminal. For protocol subsets, output limits, `monthly_cap_exceeded`, and availability failures, see [Gateway](/docs/gateway).
