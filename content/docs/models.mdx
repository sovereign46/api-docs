## Model release lifecycle

`GET /v1/admin/model-releases` lists releases; `GET /v1/admin/model-releases/{releaseId}` returns state and evidence.

| Action | Route | Result |
| --- | --- | --- |
| Create | `POST /v1/admin/model-releases` | `201`: staged release for `{ namespace, team, modelSlug }`. |
| Upload | `POST /v1/admin/model-releases/{releaseId}/upload-session` | `201`: upload URL for the declared SHA-256 and size. |
| Finalize | `POST /v1/admin/model-releases/{releaseId}/finalize-upload` | `200`: quarantined artifact metadata. |
| Validate | `POST /v1/admin/model-releases/{releaseId}/validate` | `202`: certification job queued. |
| Publish | `POST /v1/admin/model-releases/{releaseId}/publish` | `202`: registry publication queued. |
| Yank | `POST /v1/admin/model-releases/{releaseId}/yank` | `202`: serving blocked immediately; signed yank publication queued. |

An upload is not certification, and a queued publication is not serving availability. Identity review, runtime certification, release approval, publication, current transparency verification, activation, team authorization, and live inference are separate claims. Mutating release actions after create require `If-Match`; finalize, validate, publish, and yank also require `Idempotency-Key`. Read the returned release `etag` before the next mutation.

The current model-by-model evidence is listed on [Model assurance status](/docs/model-status). DeepSeek identity signatures do not create an API model row or authorize serving.

For worker integration and policy provisioning, see the [worker protocol](https://github.com/sovereign46/api/blob/main/docs/worker-protocol.md) and [policy runbook](https://github.com/sovereign46/api/blob/main/docs/deployment-trust-policy.md).

## Certified models

<Method method="GET" path="/v1/admin/models" returns="200" />

Returns catalog `models`, plus `modelPolicies` when the `team` query parameter is supplied. Rows can include unservable entries and expose certification/publication/advisory state, artifact details, and runtime metadata. Serving additionally requires **independent current registry verification**, team authorization, and an unblocked model; persisted flags alone cannot establish trust.

| Field | Meaning |
| --- | --- |
| `id` / `backendModel` | Public model ID / verified serving alias. Clients send the public ID. |
| `format` | `safetensors` for a native package, `gguf` for a GGUF artifact; older manifests may omit it. |
| `runtime` | Signed engine/version, profile digest, context/output limits, reasoning capability, and memory hints. |
| `contextWindow` / `maxOutputTokens` | Catalog limits derived from runtime metadata. |
| `certified` | The signed release/audit gate passed for the represented release evidence. It does not attest a currently loaded runtime. |
| `published` | The release is represented in the verified registry. It does not imply activation or availability. |
| `sigsumStatus` | Transparency state recorded for the release verification result, not a permanent live-health badge. |

Native safetensors use a `package.json` inventory, not a single GGUF file. Metadata verification is not evidence that checkpoint bytes are loaded or verified on a serving host. For authorized client selection and an example runtime response, see [Teams](/docs/teams-sessions).

## Team model policy

<Method method="GET" path="/v1/admin/model-policies?team={team}" returns="200" />
<Method method="PUT" path="/v1/admin/model-policies" returns="200" />

Policy determines which certified models a team may use. Grant edits remain available on a running service during registry-verification outages, subject to normal authorization and mutation checks. Saving an allowed grant does not bypass independent verification: gateway calls still return `503 model_registry_unavailable` until verification recovers, or `403 model_not_allowed` for a disallowed model.

```bash
curl 'https://api.s46.dev/v1/admin/model-policies?team=%40s46%2Fengineering' \
  -H "Authorization: Bearer $S46_ACCESS_TOKEN"

# Set MODEL_ID to a public ID from the certified catalog.
curl -X PUT https://api.s46.dev/v1/admin/model-policies \
  -H "Authorization: Bearer $S46_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: policy-$(uuidgen)" \
  -d "{\"team\":\"@s46/engineering\",\"modelId\":\"$MODEL_ID\",\"allowed\":true}"
```

Read effective authorized models from `GET /v1/teams/{team}`, not from unfiltered gateway discovery or a hard-coded default.
