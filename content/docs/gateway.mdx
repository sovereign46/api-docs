Use the `endpoint` and configured `defaultModel` from [team resolution](/docs/teams-sessions), then fetch this gateway's authenticated model discovery. The team response's `models` and `modelMetadata` are compatibility fields, not exact serving authorization. Cloud requests use a public ID returned by gateway discovery; the gateway maps it to the signed backend alias. Do not send backend aliases or hard-code an identity-only candidate.

Production model POST and discovery routes require a bearer token. They enforce current registry verification, exact signed [serving authority](/docs/serving-authority), and the caller team's exact-release grant. Explicitly sync-disabled development and airplane mode retain separate local/mock behavior; those exceptions are not the production contract.

## Chat completions

<Method method="POST" path="/v1/chat/completions" returns="200 / SSE" />

Omit `model` to use the configured team default. It must still resolve to an active exact-granted release. For a complete discovery-driven call, see the [quickstart](/docs/quickstart#call-the-gateway).

## Responses & Codex

<Method method="POST" path="/v1/responses" returns="200 / SSE" />
<Method method="POST" path="/codex/v1/responses" returns="200 / SSE" />

Both routes accept text input, message history, function calls/results, function tools, and text/JSON output formats. Send full history on each request: stored responses, nonempty `previous_response_id`, background execution, automatic truncation, and non-null `reasoning` are unsupported. Multimodal input and built-in/server tools are unsupported.

## Anthropic Messages

<Method method="POST" path="/anthropic/v1/messages" returns="200 / SSE" />

Supports text, system prompts, function tools, `tool_choice`, `tool_use`, and text `tool_result` blocks. Images, documents, thinking blocks/signatures, server tools, and context-management features are unsupported.

These are compatibility subsets, not complete vendor APIs. Unsupported Responses or Anthropic features return `400 unsupported_feature`.

## One output trajectory

Protected requests permit exactly one output trajectory. `n` and `best_of` must be absent or the integer `1`; beam-search and multi-sample extensions are rejected before usage reservation. Successful non-stream responses and streams must likewise contain one coherent index-0 trajectory and one recognized terminal finish.

## Output limits

The verified cloud cap is the smaller positive catalog value of `maxOutputTokens` and `contextWindow`, or the sole positive value. Omitted output limits default to that cap; excessive values are **rejected**, not clamped. Without either limit, the gateway supplies no catalog-derived default.

| Protocol | Accepted output-limit fields |
| --- | --- |
| Chat Completions | `max_tokens`, `max_completion_tokens` |
| Responses / Codex | `max_output_tokens`, `max_tokens`, `max_completion_tokens` |
| Anthropic Messages | `max_tokens` |

Limits must be positive integers no greater than 2,147,483,647 and the effective catalog limit. Multiple supplied aliases must agree. Invalid, conflicting, protocol-inappropriate limits and cloud `n_predict` return `400 invalid_request`.

## Reservation & settlement

Before opening the protected upstream connection, the gateway rechecks the exact authority snapshot, challenged loaded identity, route incarnation, and grant, then atomically reserves the signed worst-case request cost. `429 monthly_cap_exceeded` means no upstream request was made.

A successful non-stream response settles validated exact usage before completion.

### Streaming

A stream settles durably before emitting its success terminal:

- Chat ends with `[DONE]`.
- Responses/Codex end with `response.completed` (`response.incomplete` when output is limited).
- Anthropic ends with `message_stop`.

An upstream failure before streaming returns `502 upstream_error`. After headers are sent, inspect the protocol-specific failure form rather than HTTP status:

- Chat emits an SSE `data` object: `{ "error": { "code": "upstream_error", "message": "model stream failed" } }`.
- Responses/Codex emits an `event: response.failed` event whose response has `status: "failed"` and an `upstream_error` error.
- Anthropic emits an `event: error` event with `{ "type": "error", "error": { "type": "api_error", "message": "model stream failed" } }`.

No success terminal follows one of these failures. Missing/ambiguous usage, parser or transport failure, and client disconnect settle conservatively. Never treat an error event, truncated stream, or missing success terminal as a completed generation.

## Model discovery

<Method method="GET" path="/v1/models" />
<Method method="GET" path="/anthropic/v1/models" />
<Method method="GET" path="/codex/v1/models" />

Production discovery requires the caller's bearer token and returns only that team's exact-granted releases that are active under current serving authority. It is safe to select from this list; a global catalog row or stored default alone is not serving authorization.

OpenAI/Codex return `{ object: "list", data: [...] }`, with each entry's catalog details under `metadata`, including the immutable `releaseId`, `format`, `runtime`, `contextWindow`, and `maxOutputTokens`. Anthropic returns `{ data: [{ id, type: "model", display_name }], has_more: false }` without runtime metadata.

## Policy & availability failures

| Status | Code | Meaning |
| --- | --- | --- |
| `401` | `unauthorized` | Production discovery or inference lacks valid caller credentials. |
| `403` | `model_not_allowed` | Select a model from authenticated discovery, or have an owner/admin grant its exact active release; retired model-ID policy cannot authorize it. |
| `429` | `monthly_cap_exceeded` | The atomic monthly ledger cannot reserve the signed worst-case cost. |
| `503` | `model_registry_unavailable` | Independent registry verification is unavailable or no longer current. |
| `503` | `serving_authority_unavailable` | Deployment, activation, route, or challenged loaded identity is absent, stale, changed, or invalid. |
| `503` | `model_unavailable` | No protected serving route is available. |
| `502` | `upstream_error` | Protected upstream request or response failed. |

## Airplane-mode workers

<Method method="GET" path="/v1/workers" />
<Method method="GET" path="/v1/workers/{id}" />

Local worker discovery uses ID `local-llamacpp` and states `not_configured`, `unavailable`, `unhealthy`, `model_missing`, or `ready`. Local GGUF models use llama.cpp; native safetensors cloud packages are a separate serving path. Local model IDs map to configured backend aliases, and local output limits are clamped to local configuration.

## Upstream behavior

Production protocols normalize to OpenAI Chat Completions and dispatch through the authority-bound protected mTLS Unix-socket route. Production has no caller-selected network origin, plaintext, or bearer fallback. Caller authorization headers and cookies are not forwarded upstream.

Dedicated Anthropic/Codex passthroughs and arbitrary-model proxy/mock behavior apply only when verification is explicitly disabled. For operator provisioning, see the API repository's serving-authority and deployment documentation; those files describe source configuration, not proof that production is live.
