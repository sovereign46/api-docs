## Terminology

- **Artifact identity:** reviewers signed a digest-bound description of exact artifact bytes.
- **Runtime certification:** approved evidence binds an exact runtime/material closure and execution profile.
- **Release approval:** the release gate accepted exact evidence and subject bytes.
- **Published:** a signed release is present in the registry; this does not prove it is deployed or loaded.
- **Deployed:** signed evidence binds one exact registry release, artifact, and runtime identity.
- **Activated:** signed authority binds that deployment to a protected route, backend alias, runtime limits, and billing rates.
- **Loaded identity:** a fresh challenge binds the activation to the current serving instance and route incarnation.
- **Available:** current registry verification, exact team grant, complete serving authority, and reservable capacity all pass.

Never collapse these into an unqualified “approved”, “verified”, “green”, or “active” badge.
