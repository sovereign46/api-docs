Base URLs:

| Surface | Base URL | Use it for |
| --- | --- | --- |
| Control plane | `https://api.s46.dev` | auth, account, teams, sessions, admin, worker control |
| Harness gateway | `https://gateway.s46.dev` | OpenAI, Anthropic, and Codex-compatible model calls |

Machine-readable schema: [`/openapi.json`](/openapi.json). LLM index: [`/llms.txt`](/llms.txt).

## Build in this order

1. Check [status endpoints](/docs/operations) and wire JSON error handling.
2. Implement [auth](/docs/auth) and store device-bound access/refresh credentials.
3. Read [the current account](/docs/account), then resolve [team metadata](/docs/teams-sessions) for the team the user selected.
4. Use the returned team `endpoint`, `defaultModel`, and `models` when calling the [harness gateway](/docs/gateway).
5. If the user is an org/team admin, expose [admin routes](/docs/admin) and [model policy routes](/docs/models).
6. If you are building infrastructure, implement the [worker control protocol](/docs/worker-control).

## Core rules

- The API is org-scoped. Teams use canonical `@org/team` identifiers, for example `@s46/engineering`.
- User-facing clients use user-scoped bearer tokens from the invite-gated device flow.
- Admin authorization accepts only `owner` and `admin` roles.
- Membership roles are exactly `owner`, `admin`, `member`, and `viewer`.
- The scheduling/location field is `region`; new consumers must not use legacy `lane` terminology.
- Production clients must not embed `S46_ADMIN_TOKEN`. It is an operator bootstrap credential, not an end-user credential.

## Request conventions

Authenticated JSON endpoints use:

```txt
Authorization: Bearer <accessToken>
Accept: application/json
Content-Type: application/json
```

Browser flows may use the `s46_access` and `s46_refresh` HTTP-only cookies returned when login/refresh requests send `X-S46-Use-Cookies: true`.

Path parameters must be URL path-escaped. This matters for team IDs, emails, device IDs, worker IDs, job IDs, and session IDs:

| Value | Path segment |
| --- | --- |
| `@s46/engineering` | `%40s46%2Fengineering` |
| `dscape@s46.dev` | `dscape%40s46.dev` |
| `@dscape/auth-redirect-fix` | `%40dscape%2Fauth-redirect-fix` |

Query parameters must be query-escaped, for example `?team=%40s46%2Fengineering`.

| Group | Prefix | Start here |

## Errors

All JSON errors use the same envelope:

```json
{
  "error": {
    "code": "invalid_request",
    "message": "invalid request"
  }
}
```

Branch on HTTP status plus `error.code`; never parse `message` for control flow. See [Errors and status codes](/docs/errors).
